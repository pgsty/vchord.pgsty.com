我们欢迎来自开源社区、个人开发者及合作伙伴的各种形式的贡献。如果你有兴趣参与贡献，希望本文档能帮助你清晰了解贡献流程。

无论是资深贡献者还是刚接触开源的新手，以下指南都会非常有帮助：

- 👀 [如何参与开源贡献 | Open Source Guides](https://opensource.guide/how-to-contribute/)

## 行为准则 {#code-of-conduct}

行为准则（Code of Conduct）是一份确立项目参与者行为预期的文档。采用并执行行为准则有助于为社区营造积极健康的交流氛围。

如果你还不了解什么是行为准则，请参阅[你的行为准则 | Open Source Guides](https://opensource.guide/code-of-conduct/)。

## 参与方式 {#get-involved}

我们的社区始终欢迎热心开发者以各种方式参与其中。

<a id="simply-start-using-pgvecto-rs"></a>
### ⚽ 开始使用 `pgvecto.rs` {#simply-start-using-pgvecto-rs}

阅读并跟随[快速开始](/zh/pgvecto-rs/getting-started/overview/)指南操作。一切是否都符合预期？如果遇到问题，我们随时欢迎改进建议。你可以在 [💬 Discord](https://discord.gg/KqswhpVgdU) 上与我们交流，或在 GitHub 上[提交 Issue](https://github.com/tensorchord/pgvecto.rs/issues/new/choose)。

### 🙋 协助整理 Issue 和 Pull Request {#triaging-issues-and-pull-requests}

即使不编写任何代码，协助整理和分类新提交的 Issue 与 Pull Request 也是为项目做出重要贡献的绝佳方式：

- 如果你认为某个 Issue 未提供解决问题所需的完整细节，可以礼貌地请求补充更多信息。
- 建议合适的标签（Label），以帮助对 Issue 进行分类。
- 标记已经过时（stale）或应当关闭的 Issue。
- 询问测试计划并协助审查代码（Code Review）。

<a id="contribute-to-pgvecto-rs"></a>
### 👨‍💻 为 `pgvecto.rs` 贡献代码 {#contribute-to-pgvecto-rs}

如果你发现了想要修复的 Issue，欢迎提交 Pull Request。请先阅读[开发教程](/zh/pgvecto-rs/developers/development/)以快速上手。

### 👉 完善文档 {#improve-documentation}

大家都喜欢清晰易读的文档。如果你发现任何令人困惑或可以改进的地方，可以点击大多数文档页面底部的“编辑此页”，直接跳转到 GitHub 界面进行修改并提交更改建议。

<a id="discuss-pgvecto-rs-on-discord"></a>
### 💬 在 Discord 上交流 `pgvecto.rs` {#discuss-pgvecto-rs-on-discord}

欢迎加入我们的 [💬 Discord](https://discord.gg/KqswhpVgdU) 与社区一起交流讨论。
